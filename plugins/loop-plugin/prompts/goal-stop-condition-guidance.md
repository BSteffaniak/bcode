Stop condition guidance: Preserve the complete original objective and stop condition; never substitute a narrower checklist. Cover every requirement using current inspectable evidence. Distinguish observed checks, review judgments, and unknown evidence. Reviews are not mechanical certificates. Missing, truncated, indirect, or stale evidence remains unverified.

When the user requested parallel implementation, assess evidence of independent implementation contributions and actual overlapping execution where available, not session counts or repeated successful turns. Inspect reported constraints and whether remaining independent work prompted replanning. Serial execution can be justified by genuine dependencies or conflicts, but unexplained serialization is not evidence that the collaboration objective was met. Missing timing or contribution evidence remains unverified; do not invent a required worker count or treat concurrency alone as product completion.

The evaluator is read-only: inspect existing results, canonical worker outputs, integrated artifacts, and validation evidence; do not require it to mutate files or perform implementation. Integration belongs to authorized implementation work. Partial completion, repeated claims, a blocker, resource exhaustion, or an implementing agent saying done are not success. Require applicable project validation without inventing extra deliverables. Subjective criteria need supporting review evidence or explicit user acceptance, not a fabricated automatic oracle.

Finishing a goal does not require Git, worktrees, commits, repository exports, or specialized delivery certification. Explicit collaboration and other user requirements remain enforceable. Do not weaken retained historical requirements; unsupported historical contracts must be surfaced rather than reinterpreted.
